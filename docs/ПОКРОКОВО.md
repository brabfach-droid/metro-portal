# Запуск сайту: покроково

Ці дії потрібні один раз. Сайт і дані з’являться лише після того, як ви створите власний Supabase проєкт і завантажите файли в GitHub. Сторінки порожні, доки ви не опублікуєте записи.

## 1. Завантажте файли

Розпакуйте `metro-project.zip`. У папці `metro` є `index.html`, `404.html`, `config.js`, папки `assets`, `sql`, `docs`. Зберігайте цю структуру: не завантажуйте лише `index.html` окремо.

## 2. Створіть Supabase проєкт

1. Відкрийте [supabase.com/dashboard](https://supabase.com/dashboard), зареєструйтеся й натисніть **New project**.
2. Виберіть свою організацію, придумайте назву проєкту, створіть і **запишіть пароль бази даних у безпечному місці**. Цей пароль у файли сайту не вставляється.
3. Зачекайте завершення створення проєкту.
4. Зліва відкрийте **SQL Editor → New query**. У себе на комп’ютері відкрийте `sql/setup.sql`, скопіюйте весь вміст, вставте в редактор і натисніть **Run** один раз. Повинно з’явитися повідомлення про успішне виконання.
5. У Supabase відкрийте **Database → Tables**: мають з’явитися `news`, `documents`, `announcements`, `files`, `media`, `management`, `site_settings`, `categories`, `activity_log`, `admin_users`. У **Storage** мають з’явитися три приватні buckets: `documents`, `photos`, `downloads`.

## 3. Створіть адміністратора

1. У Supabase відкрийте **Authentication → Providers → Email**. Вимкніть публічну реєстрацію користувачів (опція може називатися **Allow new users to sign up** у **Authentication → Settings**). Для користувача, створеного вручну, не потрібна реєстрація на сайті.
2. Відкрийте **Authentication → Users → Add user → Create new user**.
3. В полі email впишіть рівно `admin@metro.example.invalid`, придумайте **власний складний пароль**. Якщо Supabase не приймає домен `.invalid`, використайте email, який ви контролюєте, і замініть рядок `admin@metro.example.invalid` у `assets/app.js` на вашу адресу **перед завантаженням сайту**. Сам пароль у код ніколи не вписуйте.
4. Позначте підтвердження email, якщо форма це пропонує, і створіть користувача. Скопіюйте його **User UID** (UUID) зі списку користувачів.
5. У **SQL Editor → New query** виконайте:

```sql
insert into public.admin_users(user_id)
values ('ВАШ_USER_UID');
```

Замініть тільки `ВАШ_USER_UID` на скопійований UUID разом із лапками навколо нього. Це надає **саме цьому користувачу** права адміністратора. На сайті логіном буде `admin`, паролем — той, який ви щойно встановили.

## 4. Вставте два публічні значення

1. У Supabase відкрийте **Project Settings → API Keys** (у новому інтерфейсі **Settings → API Keys**). Знайдіть **Project URL** і **publishable key** або старий **anon public key**.
2. Відкрийте `config.js` у текстовому редакторі й замініть:

```js
supabaseUrl: 'PASTE_SUPABASE_PROJECT_URL',
supabaseAnonKey: 'PASTE_SUPABASE_PUBLISHABLE_OR_ANON_KEY'
```

на свої два значення, залишаючи лапки, коми та `https://`. **Не вставляйте `service_role`, `secret` чи пароль бази даних.**

## 5. Завантажте сайт на GitHub Pages

1. Увійдіть на [github.com](https://github.com), натисніть **New repository**, назвіть його, наприклад, `metro-portal`. Створіть **Public** репозиторій.
2. На сторінці репозиторію натисніть **Add file → Upload files**. Перетягніть **вміст папки `metro`**, включно з папками `assets`, `sql`, `docs`, так, щоб `index.html` був **у корені репозиторію**, а не всередині додаткової папки `metro`.
3. Натисніть **Commit changes**.
4. Відкрийте **Settings → Pages**. У **Build and deployment → Source** виберіть **Deploy from a branch**; **Branch**: `main`, каталог: `/ (root)`. Натисніть **Save**.
5. Зачекайте кілька хвилин і відкрийте адресу, яку покаже Pages: `https://ВАШ_ЛОГІН.github.io/metro-portal/`. Ваша назва репозиторію може бути іншою.
6. Відкрийте `/admin` після адреси сайту, наприклад `https://ВАШ_ЛОГІН.github.io/metro-portal/admin`. Введіть логін `admin` і свій пароль.

GitHub Pages іноді потребує декількох хвилин після оновлення файлів. Якщо за прямим посиланням `/admin` видно короткий перехід, це робота `404.html`.

## 6. Перша публікація

1. В адмінпанелі відкрийте **Новини → Додати**, заповніть заголовок, текст, дату; виберіть **Опубліковано** і збережіть.
2. Відкрийте **Документи → Додати**, введіть номер вручну, виберіть PDF, виберіть **Опубліковано** і збережіть. Перевірте «Переглянути PDF» і «Завантажити PDF» у публічній частині.
3. Відкрийте **Налаштування**, додайте свої реальні контакти й увімкніть важливе повідомлення за потреби. Поля без достовірних даних залиште порожніми.
4. Перевірте кошик: перемістіть тестовий матеріал, відновіть його, перевірте архів. Архівні й видалені матеріали приховані від відвідувачів за RLS.
5. Вийдіть із адмінпанелі, відкрийте сайт в приватному вікні та перевірте, що чернетки, архів і меню адміністратора недоступні.

## Якщо щось не працює

- «Потрібне підключення Supabase»: перевірте обидва значення у `config.js`, повторно завантажте файл на GitHub.
- Не вдається увійти: перевірте email технічного користувача, пароль, підтвердження email та UUID у `admin_users`. Логін у формі — завжди `admin`.
- Не завантажується PDF: перевірте, що `sql/setup.sql` виконався до кінця, документ опублікований і файл є в приватному bucket `documents`.
- Виникла помилка доступу: перевірте RLS policies з `sql/setup.sql`, не вимикайте RLS задля виправлення.
- Категорії документів відсутні: перевірте, що SQL виконувався повністю, а не вибраний його фрагмент.

Власний домен згодом підключається в **GitHub → Settings → Pages → Custom domain**. Після налаштування DNS файли сайту змінювати не потрібно: адресний префікс визначається автоматично.
