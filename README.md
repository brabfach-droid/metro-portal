# КП «Голосіївський метрополітен»

Інформаційний портал вигаданого підприємства. Працює на GitHub Pages і Supabase без власного сервера. Увесь вміст, окрім початкових текстів із ТЗ, вводиться через адмінпанель. Не використовуйте портал як джерело інформації про реальне підприємство чи місто.

## Швидкий запуск

Відкрийте **[docs/ПОКРОКОВО.md](docs/ПОКРОКОВО.md)**. Там описані всі натискання в Supabase і GitHub для першого запуску. Потрібні безкоштовні облікові записи на обох сервісах. Ніякі паролі та `service_role` ключі не додавайте у репозиторій.

### Структура

- `index.html`, `404.html`: сторінка й підтримка прямого відкриття `/news`, `/documents`, `/admin` на GitHub Pages.
- `config.js`: лише публічні URL Supabase та publishable/anon key.
- `assets/app.js`: сторінки, пошук, авторизація, CMS, файли.
- `assets/style.css`, `assets/favicon.svg`: адаптивний стиль.
- `sql/setup.sql`: таблиці, зв’язки, індекси, RLS, Storage policies.
- `sql/create-admin.sql`: шаблон додавання першого адміністратора.
- `docs/ПОКРОКОВО.md`: інструкція для початківця.

### Сторінки

`/`, `/news`, `/news/:id`, `/documents`, `/documents/:id`, `/pdf/:id`, `/announcements`, `/announcements/:id`, `/files`, `/files/:id`, `/media`, `/depot`, `/about`, `/contacts`, `/search?q=...`, `/archive`, `/admin`.

На GitHub Pages фактична адреса має префікс `/назва-репозиторію/`. На власному домені префікса немає. `404.html` перенаправляє прямі запити на стартову сторінку й відновлює адресний рядок. Важливо: GitHub Pages фізично відповідає кодом HTTP 404 на прямі вкладені URL перед цим переходом; сайт працює, але для пошукових систем такі URL не є повноцінними сторінками з HTTP 200. Для строгого SEO й автоматичного sitemap потрібен хостинг із rewrite та генерація сторінок.

### Модель і доступ

Supabase Auth з технічною адресою адміністратора, форма входу використовує логін `admin`. Пароль задається в Supabase Dashboard. `admin_users` містить UUID дозволеного користувача. Рядки `draft`, `archived` та кошик не читаються публікою. Публічні списки читають тільки `published` без `deleted_at`. Публічний архів показує порожній список, якщо архівні записи приховані RLS: їх можна бачити в адмінпанелі й опублікувати знову. Цей вибір відповідає вимозі ТЗ про читання публікою лише статусу `published`.

Storage приватний: `documents` (PDF), `photos` (зображення), `downloads` (файли). Перегляд відбувається за часовими підписаними URL, які створює клієнт після перевірки RLS. При заміні застосунок прибирає старий об’єкт після успішного збереження запису, якщо він більше ніде не використовується; при остаточному видаленні спочатку прибирає запис, потім невикористаний файл. Якщо Supabase Storage тимчасово недоступний, може знадобитися вручну прибрати залишок у Storage Dashboard.

Пошук по українських словах і часткових збігах працює в браузері на завантажених опублікованих матеріалах. Поточна реалізація отримує до 500 матеріалів кожного типу за запит (в адмінсписках до 1000); для великого архіву потрібна серверна пагінація й повнотекстовий індекс. Фото завантажуються з `loading=lazy`, великі файли й PDF лише при відкритті. Текстовий редактор приймає звичайний текст із переносами рядків без HTML; розмітка HTML не вводиться.

### Що можна редагувати

Новини, документи, оголошення, файли й фото мають статуси «Чернетка», «Опубліковано», «Архів», кошик та остаточне видалення. У новинах є закріплення, автор, обкладинка й кілька фото. У документах номер вводиться вручну. В адмінці доступні керівництво, опис підприємства й ТЧ-1, контактні поля та важливе повідомлення. Категорії документів створює SQL; інші категорії можна додавати SQL-запитом `insert into public.categories(kind,name,position) values ('news','Назва',1);` із заміною `news` на потрібний тип. Для зв’язку з ТЧ-1 додайте «ТЧ-1» у заголовок або текст пов’язаних матеріалів.

### Перевірка

Синтаксис `assets/app.js` перевірено `node --check`. SQL і реальні операції Auth/Storage/RLS потребують запуску у вашому Supabase проєкті; жодних робочих ключів у поставці немає. Після підключення перевірте сценарії з інструкції.

### Безпека

Не додавайте `service_role` або secret key до frontend. Publishable/anon key є публічним за задумом Supabase; доступ регулює RLS. Вимкніть публічну реєстрацію в Supabase Auth. Пароль адміністратора зберігається лише у Supabase Auth. Дані в браузері екрануються перед виведенням, довільний HTML у новинах не виконується.
